# CHERAGHI ACADEMY MASTER

## Trigger
وقتی کاربر درخواست ادامه/ساخت/بازبینی مقالات آکادمی از دفترچه آزمون وکالت را می‌دهد، این Skill را اجرا کن.

## 1) Load State
- فایل وضعیت آزمون را بخوان.
- اولین بسته 4 سؤالی با وضعیت TODO یا NEEDS_REVIEW را انتخاب کن.
- بسته‌های DONE را بدون درخواست صریح بازنویسی نکن.
- اگر current_batch وجود دارد، همان را ادامه بده.

## 2) Source Guard — اجباری
- Skill `CHERAGHI-SOURCE-GUARD` را اجرا کن.
- متن سؤال و گزینه‌ها را فقط از فایل رسمی/اصلی استخراج کن.
- شماره سؤال، گزینه، پاسخ یا ماده را از حافظه حدس نزن.
- وجود منبع در وب به‌تنهایی کافی نیست؛ متن دقیق باید در دسترس pipeline باشد.
- اگر منبع ناقص/مبهم است: STOP = NEEDS_SOURCE_REVIEW.

## 3) Answer Key Verification
- کلید رسمی آزمون و اصلاحیه‌های رسمی را بررسی کن.
- در صورت تعارض، اصلاحیه رسمی مقدم است.
- اصلاحیه‌های دفترچه C سال ۱۳۹۸ از state خوانده شوند؛ دست‌نویس یا حافظه مقدم نیست.
- اگر پاسخ رسمی محل اختلاف است، اختلاف را شفاف ثبت کن و Final نده تا بررسی شود.

## 4) Legal Analysis
Skill `CHERAGHI-LEGAL-ANALYST` را اجرا کن. برای هر سؤال:
1. متن دقیق سؤال
2. چهار گزینه
3. پاسخ صحیح
4. مبنای قانونی/اصولی
5. تحلیل مرحله‌به‌مرحله
6. علت رد هر گزینه غلط
7. دام تستی
8. مثال ساده
9. نکته دکتر چراغی
10. نکته طلایی آزمون

## 5) Dr Cheraghi Note
پس از تأیید تحلیل، Skill `CHERAGHI-DR-NOTE` اجرا شود.
- 2 تا 5 جمله.
- ساده، کاربردی و آموزشی.
- تکرار تحلیل رسمی نباشد.
- هیچ نظر شخصی، حکم یا ادعای ساختگی به نام دکتر چراغی تولید نکن.
- اگر سؤال `NEEDS_LEGAL_REVIEW` است، این بخش تولید نشود.

## 6) Teaching Style — بسیار ساده، محاوره‌ای و قابل فهم
هدف این بخش این است که دانشجوی مبتدی با یک بار خواندن، مفهوم را بفهمد؛ نه اینکه فقط با متن رسمی روبه‌رو شود.

### قواعد لحن
- لحن آموزشی، صمیمی و بسیار روان باشد؛ نه خشک و دانشگاهی.
- از تقلید عینی سبک هیچ نویسنده مشخصی خودداری کن؛ فقط از ویژگی‌های عمومی آموزش خوب استفاده کن: توضیح مرحله‌ای، مثال‌محور، جمله‌های کوتاه، و ساده‌سازی بدون تحریف.
- هر اصطلاح حقوقی لازم را حفظ کن، اما بلافاصله به زبان ساده ترجمه کن.
- از جمله‌های طولانی و چندلایه تا حد ممکن پرهیز کن.
- هر پاراگراف باید فقط یک ایده اصلی داشته باشد.
- هرجا متن رسمی قانون می‌تواند دانشجو را گیج کند، بعدش یک بخش `به زبان ساده` اضافه کن.
- از شوخی زیاد، لحن بچگانه یا بی‌احترامی به مخاطب خودداری کن؛ صمیمی باش، اما حرفه‌ای بمان.

### فرمول توضیح هر قاعده
برای هر قاعده مهم، این ترتیب را اجرا کن:
1. `اول ببین سؤال چی می‌خواد`
2. `قاعده قانونی دقیق`
3. `به زبان ساده`
4. `یک مثال خیلی ساده`
5. `دام طراح`
6. `اگر فقط یک چیز یادت موند، اینو یادت بمونه`

### تست فهم‌پذیری
بعد از نوشتن هر بخش از خودت بپرس:
- آیا یک دانشجوی مبتدی با یک بار خواندن می‌فهمد؟
- آیا اصطلاح سخت بدون توضیح مانده؟
- آیا می‌توان همان معنا را با جمله کوتاه‌تر گفت؟
اگر پاسخ نامطلوب بود، همان بخش را ساده‌نویسی کن؛ بدون حذف دقت حقوقی.

### ممنوع‌ها
- ساده‌سازی‌ای که باعث تغییر حکم حقوقی شود ممنوع است.
- اصطلاح قانونی مهم را با معادل عامیانه غلط جایگزین نکن.
- برای جذابیت، داستان یا مثال ساختگیِ حقوقیِ مشکوک نساز.
- از جملات کلیشه‌ای مثل «همان‌طور که می‌دانید» یا «لازم به ذکر است» تا حد امکان استفاده نکن.

## 7) Learning Design — هدف نزدیک‌شدن به 10/10 آموزشی
برای هر سؤال، بعد از تحلیل اصلی این لایه‌ها اجباری است:

### A) جمع‌بندی 20 ثانیه‌ای
در پایان هر سؤال یک باکس `جمع‌بندی 20 ثانیه‌ای` بساز.
- حداکثر 3 تا 5 خط.
- فقط قاعده اصلی + کلید تشخیص پاسخ + دام مهم.

### B) مقایسه دام‌های مشابه
برای هر مقاله حداقل یک جدول/باکس مقایسه‌ای بساز.
- ستون پیشنهادی: `موضوع | قاعده درست | دام طراح | کلید تشخیص`.
- فقط از منابع معتبر استفاده کن.

### C) تست تثبیت یادگیری
پس از هر سؤال، 1 تست تمرینی جدید و یونیک بساز؛ فقط اگر مبنای قانونی آن کاملاً تأییدشده است.
- کپی سؤال اصلی نباشد.
- همان مفهوم را با سناریوی متفاوت بسنجد.
- 4 گزینه + پاسخ صحیح + توضیح 2 تا 4 جمله‌ای داشته باشد.
- اگر ساخت تست امن نیست، `NEEDS_LEARNING_REVIEW` ثبت کن.

### D) بازیابی فعال
در پایان مقاله بخش `خودت را امتحان کن` بساز:
- 4 پرسش کوتاه بدون پاسخ فوری.
- پاسخ‌ها در بخش جداگانه `پاسخ مرور سریع` قرار گیرند.

## 8) Long-form Article Standard
مقاله باید یک محتوای آکادمی واقعی و مستقل باشد، نه پاسخنامه کوتاه.
- H1 طبیعی
- مقدمه
- نقشه یادگیری مقاله
- فهرست 4 سؤال
- چهار بخش تحلیلی کامل
- برای هر سؤال: قاعده قانونی + به زبان ساده + مثال + دام + نکته دکتر چراغی + جمع‌بندی 20 ثانیه‌ای + تست تثبیت
- حداقل یک جدول مقایسه دام‌ها
- بخش خودت را امتحان کن + پاسخ مرور سریع
- جمع‌بندی
- نکات مرور سریع
- FAQ
- منابع/مستندات
- CTA مرتبط برای PDFها و دوره‌ها، بدون لینک یا ادعای ساختگی

### Word-count policy
- هدف استاندارد هر مقاله: 2800 تا 4000 کلمه.
- حداقل قابل قبول: 2600 کلمه، مگر اینکه افزودن متن بیشتر باعث تکرار یا افت کیفیت شود.
- سقف مصنوعی وجود ندارد.
- اصل حاکم: «گسترش فقط با افزودن ارزش».

## 9) SEO Routing — کلیدواژه اختصاصی هر مقاله
Skill `CHERAGHI-SEO-QC` را اجرا کن.
- Focus Keyword دو مقاله در یک دفترچه نباید یکسان باشد.
- موضوع/بازه سؤال در Long-tail بازتاب داشته باشد.
- Keyword Cannibalization بررسی شود.
- اگر Semrush در دسترس است، intent، volume/KD موجود، related terms، questions و content gap بررسی شود.
- اگر Semrush در دسترس نیست یا API Unit کافی نیست: `SEO_DATA_LIMITED`؛ هیچ داده‌ای حدس نزن.

برای سؤال‌های 21 تا 24 آیین دادرسی مدنی 1398، seed:
`تحلیل سوالات ۲۱ تا ۲۴ آیین دادرسی مدنی آزمون وکالت ۱۳۹۸`

تولید کن:
- primary/focus keyword یکتا
- 4 تا 10 related/secondary keywords
- search intent
- SEO title
- meta description
- slug
- H2/H3 map
- FAQ opportunities
- internal-link suggestions

Keyword stuffing ممنوع است.

## 10) Quality Gates
برای هر سؤال:
- SOURCE_MATCH
- KEY_MATCH
- LEGAL_SUPPORT
- LOGIC_CONSISTENCY

Learning Gates:
- BEGINNER_FRIENDLY = true
- LEGAL_TERM_EXPLAINED = true
- SIMPLE_LANGUAGE_WITHOUT_DISTORTION = true
- QUICK_RECAP_PRESENT
- PRACTICE_TEST_PRESENT_OR_JUSTIFIED_SKIP
- ACTIVE_RECALL_PRESENT
- CONFUSION_TABLE_PRESENT
- NO_MISLEADING_SIMPLIFICATION

برای مقاله:
- NO_FABRICATION
- NO_DUPLICATION
- READABILITY
- SEO_NATURAL
- UNIQUE_FOCUS_KEYWORD
- NO_KEYWORD_CANNIBALIZATION
- DR_CHERAGHI_NOTE_PRESENT
- ALL_4_QUESTIONS_COMPLETE
- ARTICLE_SCHEMA_VALID
- WORD_COUNT_POLICY_PASS
- LEARNING_DESIGN_PASS

اگر هر Gate بحرانی شکست خورد: status = NEEDS_REVIEW و Publish ممنوع.

## 11) Featured Image Brief
بعد از قفل نهایی محتوا، Brief تصویر شاخص تولید کن:
- فقط عنوان مقاله روی تصویر مگر کاربر خلافش را بخواهد.
- هویت بصری واقعی سایت چراغی: روشن، مینیمال، رسمی و هماهنگ با Accent واقعی سایت.
- از رنگ‌سازی حدسی خودداری کن.
- بدون متن توضیحی اضافه.
- الگو: `سوالات X تا Y [نام درس] | آزمون وکالت [سال] | دفترچه C`.

## 12) CTA
در هر مقاله دو CTA طبیعی:
- مشاهده/خرید PDFها و جزوات آموزشی مرتبط
- مشاهده/ثبت‌نام دوره‌های آموزشی مرتبط

قواعد:
- CTA مرتبط با موضوع مقاله باشد.
- فشار روانی یا تضمین قبولی ممنوع.
- اگر URL واقعی نداریم، لینک نساز؛ Placeholder مشخص تولید کن.

## 13) Publish Policy
- پیش‌فرض: DRAFT.
- فقط با تأیید صریح یا Rule تأییدشده پروژه به APPROVED/PUBLISHED تغییر بده.
- حداقل 5 مقاله متوالی باید تمام Gateها را پاس کنند تا Publish خودکار پیشنهاد شود.

## 14) Tool Routing
- Drive/Files = source truth
- Web = قوانین، اصلاحیه رسمی و verification
- Semrush = SEO intelligence
- Canva/Image = featured image
- GitHub/Codex = workflow/plugin code, version control, tests
- n8n = orchestration فقط
